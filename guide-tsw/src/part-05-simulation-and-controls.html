Simulation and controls: SimuGraph, VHIDs, and where your Lua goes

In TSC the sim blueprint and the Lua script gave the locomotive its character. In TSW that work splits into the SimuGraph (a node graph of axles, motors, cylinders and valves integrated every frame), VHID control pairs, and a thin Blueprint event graph that copies control values into the graph. This part builds the minimal drivable set and shows how a TSC script translates.

1 · The Simulation Asset and its node types

Create it with right-click ▸ Miscellaneous ▸ Simulation Asset in Simulation/ and assign it to the RVM's Simulation component. Double-clicking opens the SimuGraph editor. The asset holds PresetConfigData[] (named configurations with Parked / RunningStopped / RunningActive snapshots) and the runtime graph: a Nodes[] array, each with a name, a struct type such as SimulationNode_Axle, and pins connected to other nodes. verified

2 · The minimal SimuGraph that drives

  1. Axle1, Axle2: set wheel radius (build sheet axles[].radius_m) and mass per axle; chain their axle pins. The physics component's ConnectedWheels is filled at runtime from these.
  2. VoltageSource → Motor → Gearbox → Axle1.
  3. PowerInput: map InputValue 0..1 to the motor's control pin (on Thomas this goes through a Chopper; try the motor's power input first, insert a ChopperV2 if the node refuses).
  4. ReverserPosition.OutValue0 → Motor.ReverseFieldPolarity via the parameter-link table (§3).
  5. BrakeInput → BrakeCylinder → BrakeRigging → BrakePad_1/2 → Axle1/2.
  6. Save; record a Default configuration's RunningStopped preset with brake applied and throttle at zero.
Steam, diesel, electric

Thomas is labelled “Steam” for the player but is simulated as an electric motor and a chopper: the graph only has to feel right. Start every loco this way; swap in the diesel-engine or boiler blocks from the node palette when the rest works. verified

A hauled wagon's graph is smaller still

The streamer's hopper rolled behind a locomotive with only six nodes: two Bogie nodes with their pivot offsets (the first at X = −5.16 m, the second positive) and four Axle nodes, each with gauge 1520 mm, the wheel radius, an offset of about ±0.95 m from its bogie, and the bogie named as parent. No motor, no brakes: a wagon has nothing to push and the loco does the braking for now. When one bogie node was accidentally given the other's offset the wagon jumped and twisted as soon as it was hauled; fixing the sign fixed it. The real air-brake distributor is the part he had not solved yet. community

Presets. Each configuration stores three states: Parked (cold and dark), RunningStopped (ready, brakes on), RunningActive (moving). The game applies one at spawn (LastAppliedPreset = RunningStoppedPreset). Thomas's were all unrecorded, so defaults were used. Record yours by setting the graph into each state in the editor and saving; it is what lets a scenario spawn your engine already running.

6 · The RVM event graph: glue, not simulation

For each lever, bind OnOutputValueChanged and call the set-simulation-parameter node with a struct variable: Simulation / PowerInput / InputValue, likewise ReverserPosition and BrakeInput. Three bindings, three calls, nothing else. Thomas's graph additionally reads Axle3 / SpeedAtRail_MS through a threshold delegate (told when speed crosses 0.2 m/s instead of polling), raises OnVehicleSpeedChanged for the view's wheel-blur, and binds the physics component's coupling, door-lock, headlight and preset events. verified

Rule of thumb

If you find yourself computing physics in Blueprint, that logic belongs in the SimuGraph. The graph copies VHID outputs into SimuGraph inputs, reads a few outputs, and raises events.

Worked example: the trolley poles

The TSC script (examples/lua/TrolleyPole.lua) keeps two poles with states raised / lowered / dewired, raises and lowers them on a control, dewires above a speed and cuts traction while dewired. In TSW:

  1. Controls: two PushButton VHIDs PoleFront, PoleRear (TOGGLE) on the RVM, hitboxes on the roof hatch or the cab switch on the RVV.
  2. Animation: two clips Pole_F, Pole_R (lowered at frame 0, raised at the end) in VirtualHIDSequenceEntries: the pole follows the button's 0..1 output over the button's travel time. Export them from the same keyed objects you made for TSC.
  3. Dewirement: a RailVehicleParameterChangedDelegate on Axle1.SpeedAtRail_MS at the dewire speed; in the handler set the button's input back to 0 (pole drops) and set a ValueConverter node PoleContact to 0.
  4. Traction cut: a parameter link PoleContact.OutValue0 → VoltageSource (or an Expression gating PowerInput): no contact, no volts. That part of the Lua is now four nodes.
  5. Sounds and sparks: the RVA binds the pole VHIDs for the clunk; the RVV binds them for a Niagara spark at a socket_PoleHead socket.

8 · Simple Physics: the fallback

The physics component carries a complete SimplePhysics block (powered flag, max effort, effort-vs-speed curve, max speed, braking effort). It is filled on Thomas even though he has a full graph, and the wiki's setup guide says to fill it for powered vehicles. It is almost certainly what AI-driven and vault-stored vehicles use. Whether a vehicle with no SimuGraph at all is drivable has not been tested; the minimal graph above is cheap, so build it rather than relying on the fallback.
