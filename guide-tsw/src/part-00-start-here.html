Where the pipelines branch

All three games want the same thing from Blender first: a clean, correctly scaled model with named parts and keyed moving pieces. Then they part company. TSC wants an .igs and XML blueprints; TF3 wants FBX files per LOD and its Model Editor metadata; TSW wants one skeletal mesh with an armature, a set of short animation clips, and a family of Unreal Blueprints and data assets that you build in the editor. The web viewer takes a glTF. One master scene feeds all four.

The plugin folder

Your vehicle is a content plugin (Edit ▸ Plugins ▸ New Plugin ▸ Content Only). Never put files in /Game/ or in a Dovetail DLC folder. The layout below is Thomas's real plugin and the wiki's recommended shape; the add-on's output and the editor helper (Part 7) follow it. verified

Conventions used in this set

ConventionMeaning
PrefixesRVD_ RVM_ RVV_ RVA_ SA_ SK_ SM_ ABP_ SC_ FC_ M_/MI_ UCX_ FRM_ WBP_: definition, model, view, audio, simulation asset, skeletal/static mesh, anim blueprint, sound cue, float curve, material, collision, formation, widget. verified
Suffixes_F/_B front/back, _L/_R left/right; a control in both cabs is Throttle_F and Throttle_B.
AxesUE: X forward, Y right, Z up, centimetres. Blender after the branch rotation: X forward, Y left, Z up, metres. A Blender point (x, y, z) m is (100x, −100y, 100z) cm in the editor. check
BonesRoot → Body_Pivot → …; axles axle1..n front to back; bogies bogie1..n; buffers buffer_fl/fr/bl/br; all other bones keep the TSC base name.
SocketsEmpties named SOCKET_<name> parented to a bone; the importer turns them into skeleton sockets named <name>.
FiguresBlue = RVM, green = RVV, orange = RVA, purple = data, crimson = the Blender side.
verified / check / communityRead from the running editor by the inspection this set is based on / inferred or untested, confirm in your editor / done on stream by a community creator and worth copying.

Glossary

TermMeaning
PC EditorDovetail's Unreal 4.26 editor build of TSW (project TS2Prototype) that loads the game content and lets you add plugins and play routes in the editor.
RVD / RVM / RVV / RVARail Vehicle Definition / Model / View / Audio. Figure 0.2.
SimuGraph, SADovetail's node-based physics simulation and the asset that stores one graph. Nodes are axles, motors, cylinders, valves; Blueprints read and write named parameters.
VHIDVirtual Human Interface Device: any control the player can touch. A logic component on the RVM paired by name with a hitbox component on the RVV.
Interaction environmentA position a person can occupy (driver, second man, guard). Controls, seats and cameras belong to one; keys only work in the one you occupy.
Input identifierThe string that maps a keyboard binding to a VHID: SimpleThrottle, Throttle, Reverser, TrainBrake, Horn, Headlights.
Animation Blueprint (ABP)The graph that poses a skeletal mesh each frame. TSW's parent class RailVehicleAnimInstance does the axle spinning, bogie yaw, buffer compression and VHID clip scrubbing.
SocketA named attachment point on a bone (seat, wheel contact, lever, audio).
UCX meshA separate low-poly static mesh used as walkable collision (and sometimes audio occlusion).
PresetEither a SimuGraph state snapshot (Parked / RunningStopped / RunningActive) or a bundle of VHID target values on the physics component (Headlights On…).
FormationOrdered list of RVDs that spawns as one train. Nothing spawns an RVD directly.
CookedEditor data stripped. Dovetail's shipped vehicles are cooked: you can spawn and read them, not open their graphs. Your plugin is source.
Play In Editor (PIE)Pressing Play on a route inside the editor; your vehicle can be spawned and driven without packaging.
