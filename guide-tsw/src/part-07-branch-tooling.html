Part 7

The branch tooling: objects to bones, the build sheet, the editor helper

Reference for the three things this branch ships: a Blender add-on that converts the TSC object hierarchy into a skinned skeletal mesh with value-scrubbed clips and sockets, the build sheet it writes for the numbers you type in the editor, and a Python script for the editor's own console that does the importing and the data assets. How each was tested, how to extend them, and what to script next.

1 · Where the tool sits

2 · Installing and using the add-on

  1. Blender ▸ Edit ▸ Preferences ▸ Add-ons ▸ Install… ▸ tools/blender/tsw_export_prep.py ▸ tick it.
  2. In the 3D viewport press N ▸ TSC tab ▸ panel TSW branch.
  3. Export root (receives <Name>/), Name (MyLoco → SK_MyLoco_Ext), Cab collection (objects that become SK_MyLoco_Cab), wheel clip frames (60), bone length (cosmetic).
  4. Preview rig in scene: builds the armature, the joined meshes, the sockets and the clip actions in a collection _tsw_export. Select the armature, open the Action editor, scrub a clip; check bones sit on hinges and sockets are where you expect. Delete the collection when done (or just export: the export rebuilds it).
  5. Export TSW FBX set + build sheet. The report is in the Text Editor as TSW_Export: bones, sockets, clips, files.

3 · What it reads: the tags

PropertyOnValueEffect
tsw_boneObjectbone nameForce a bone for this object (even if static) and/or name it.
tsw_clipObjectclip nameName of the clip this object's animation goes into. Default: the NLA strip name, else web_anim, else the action name. Several objects with the same clip name bake into one clip.
tsw_vhidObjectRVM component nameRecorded in the build sheet as “this VHID drives this clip” for the ABP's VirtualHIDSequenceEntries.
tsw_socketEmptysocket nameExported as SOCKET_<name> under the nearest bone ancestor. Empties named socket_<name> work without the property.
tsw_collisionMesh1Joined into UCX_<Name>_Collision and exported as a static mesh instead of being skinned.
tsw_cabObject1Goes into the cab mesh (same as being in the cab collection).
tsw_skipObject1Left out.

Recognised without tags: wheel objects …boNNwhNN → axleN; bogie objects …boNN → bogieN; names containing “buffer” → buffer_fl/fr/bl/br; tsc_driver → SOCKET_DriverSeat; tsc_coupling_front/rear → SOCKET_Coupler_F/B + coupler numbers; any object with keys or strips → a bone. Dropped: LOD 2+, shadow_, primarydigits, light_fwd/rev. Keep the lower-case axleN / bogieN names: Thomas uses them and the editor's ABP auto-detects them (Part 2 §2).

4 · What it does, step by step

The FBX call for the mesh files, if you want to match it by hand:

bpy.ops.export_scene.fbx(filepath=path, use_selection=True, object_types={"ARMATURE", "MESH", "EMPTY"},
    apply_unit_scale=True, apply_scale_options="FBX_SCALE_ALL", axis_forward="-Z", axis_up="Y",
    use_mesh_modifiers=True, mesh_smooth_type="FACE", add_leaf_bones=False, use_armature_deform_only=False,
    primary_bone_axis="Y", secondary_bone_axis="X", bake_anim=False, path_mode="COPY")
# clips: object_types={"ARMATURE"}, bake_anim=True, scene range = clip range, scene renamed to the clip (names the take)

6 · The editor helper

tools/tsw/tsw_editor_setup.py runs inside the editor (Output Log ▸ Cmd: py "C:/path/tsw_editor_setup.py") after you edit its CONFIG block (sheet path, plugin root, friendly name, max speed). It then:

  1. creates the plugin folder layout;
  2. imports SK_<Name>_Ext.fbx as a skeletal mesh with a new skeleton, and the cab onto that skeleton;
  3. imports every Animation/*.fbx as an AnimSequence on it;
  4. imports the UCX static mesh (collision generation off);
  5. creates RVD_<Name> and sets name, max speed, flags and bounds; links the RVM/RVV classes if they already exist;
  6. creates an empty FRM_<Name>;
  7. prints the physics numbers (Y negated), buffer and coupler offsets, the ABP list contents and the VHID entries.

It does not create the RVM, RVV or ABP Blueprints or the SimuGraph: component editing inside Blueprints is not exposed to Python in 4.26. Every step is wrapped so a failure prints and the script continues; property names that do not resolve are reported with “set it in the Details panel”. check on first use: the data-asset factory call and the RailVehicleDefinition property names are the two things most likely to need a small edit.

7 · How it was tested

  1. Scene: tools/tsw/build_test.py builds a TSC-named loco (+Y forward): body, roof, LOD-2 twin and a shadow_ mesh (to be dropped), four doors keyed 0–24 with tsw_vhid, two bogies with three wheels each (cylinders rotated so their local axes do not match the world, to prove the world-aligned bones), a pantograph base → lower arm → upper arm → head chain keyed 0–30, a wiper with its action in an NLA strip, four buffers, a driver empty, two coupling empties, a custom audio socket, a cab collection with a throttle lever keyed 0–20, and a tagged collision mesh.
  2. Rig maths: for the door, the pantograph (both arms, one as a child of the other), the wiper (NLA) and the lever, the bone's world pose at sampled frames matched the object's motion applied to the rest frame to within 1e-4; a vertex of the static pantograph head followed the upper-arm bone at frame 30; the generated wheel clip rolled the wheel top towards +X.
  3. Output: 22 bones (Root, Body_Pivot, 4 doors, 2 bogies, 6 axles, 2 pantograph arms, wiper, 4 buffers, lever), 17 sockets, 8 clips (4 doors, pantograph, wipers, throttle, wheels), ext mesh 416 vertices, cab mesh 8 vertices, UCX, build sheet. No rig left in the scene afterwards.
  4. Round trip: re-importing the exterior FBX gave the same bone tree with the same parents, every socket as an empty under the right bone at the right position, and the mesh at 18.5 × 3.0 × 4.16 m; importing Door_L1.fbx gave a take named Door_L1 whose door bone sat at 79.8° on the last frame (keyed 80.2°); Wheels_FullRotation.fbx gave 174° at frame 29 of 60.

Repeat it with python tools/tsw/build_test.py <out> under the bpy wheel or blender -b --python tools/tsw/build_test.py -- <out>; it prints ERRORS: [] when all checks pass.

8 · Extending the tools

WantChange
A bone the game should move that has no animation yet (future sander, cab blind)Give the object tsw_bone.
Rods and valve gear in the wheel clipKey one revolution of wheels + rods in the master as an action named Wheels_FullRotation (or tag it tsw_clip); the add-on bakes it instead of generating the plain one.
Two doors on one buttonSame tsw_clip on both; one clip, one VHID entry.
Hand-made LOD meshesExport the LOD-2 twins as a second run with tsw_skip on LOD 1 and the twins renamed to LOD 1, then import as LOD levels. Or let the editor reduce.
Different forward rotationROT_Y_TO_X at the top of the file; identity if your master already faces +X.
Dense keys too heavybake_anim_simplify_factor in export_tsw (0 = keep every frame).
Materials from the TF3 branchExport the PBR sheets with the TF3 packer, set roughness = 1 − gloss, repack ORM; the FBX only needs the base colour to find the material by name.

10 · Known limits

  • Objects are converted, not armatures: if the master already has an armature (valve gear rigged with bones), its bones are not merged; export that mesh by hand.
  • Shape keys are not baked into bones; a part that must deform (a bellows) needs a hand-made rig.
  • Every bone is world-aligned (X forward, Y left, Z up). Fine for everything scrubbed from clips; if the engine's Axles spin axis turns out to be a bone-local axis other than the one the generated wheel clip uses, keep the clip route (exact) and tell the add-on's author.
  • An object with two overlapping NLA strips in different tracks is baked as their blend, which is probably not what you keyed; keep one strip per object or set tsw_clip and separate the tracks.
  • Materials and textures are not converted; the FBX carries names and base colour only. Build the master material in the editor.
  • The editor helper is untested in the editor and creates no Blueprints; expect to fix one or two property names on first run.
