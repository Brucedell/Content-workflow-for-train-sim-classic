Transport Fever 3 · Vehicle Workflow Guide
Part 6

Build, test and publish

The TF3 iteration loop is shorter than TSC's because the Model Editor reloads on file change and validates on demand. This part sets up that loop, gives an in-game test order for rail vehicles, covers mod packaging for mod.io, and ends with a symptom table.

2 · The mod skeleton

modinfo.json  (display data for the mod browser)
{
  "name": "My Loco",
  "description": "…",
  "authors": [ { "name": "you", "role": "CREATOR" } ],
  "minorVersion": 0,
  "severityAdd": "NONE", "severityRemove": "WARNING",
  "tags": [ "Train", "Vehicle" ]
}

Keys shown are the TF2 convention; the manual only states what the file is for (name, description, authors, preview image, dependency note). check against the Mod Definition page.

mod.json  (technical definition)
{
  "dependencies": [ "someone_othermod_1" ],
  …
}

“Most important is the specification of the correct dependency” when you reference another mod's meshes/materials with modid::. manual Other fields check.

Also: strings.json for the _("…") keys used in description, and the preview image.

Create the mod folder in the staging area before the first import so the Model Editor can select it as the save target. manual

4 · Testing in the game

  1. Enable the mod for a new or existing game (mod manager). check menu names.
  2. Buy the vehicle in a rail depot: it must appear in the store with its icons, name and description (needs filterTags matching the depot, default is fine, and the year within availability). manual
  3. Couple a wagon and run a line: watch coupling distance, bogie tracking in curves, wheel spin rate, sagging or floating (axle origins).
  4. Stop at a station: doors open on the platform side after arrivalDelay, passengers board, doors close before departure.
  5. Reverse at a terminus: headlights/tail lamps switch ends; pantograph instance switches; crew seat moves to the leading end.
  6. Night: lights on; emissions and speed in the vehicle window as intended.
  7. Multiple unit and repaint variants appear grouped in the store if configured.

5 · Repaint and variant workflow

  • Liveries: one .mtl per re-textured material, one .mdl per variant pointing at them in every LOD, new icons, groupFileName to group them. manual
  • If you repaint someone else's vehicle, obtain permission, use a different modId and declare the dependency. manual
  • Work from texture source files, not the shipped .dds. manual
  • The Model Editor's Copy tool duplicates a model into another mod; Rename does search/replace on file names; Convert migrates TF2 models. manual

6 · Publishing

  • TF3 mods are shared through mod.io; the manual's “Publish a mod” page was not supplied check its upload steps and the Curated Mods Program rules.
  • Ship only what is yours and new: do not re-ship base-game or other mods' files; reference them with ::/ and modid::/ instead. manual
  • Include all three UI icons per model, strings.json entries for every _("…"), and a preview image.
  • Run Validate on every model (Tools ▸ Validate handles many at once). manual
