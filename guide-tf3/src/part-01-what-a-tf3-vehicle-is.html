What a Transport Fever 3 vehicle actually is

A TF3 vehicle is a Lua table: a tree of named nodes pointing at meshes and materials, plus metadata structs that tell the simulation which nodes are axles, where people sit, how much it weighs and how fast it goes. The game does the driving.

3 · Node names are the contract

“In comparison to Transport Fever 2, most of the metadata refer to model parts by using the node names. Hence it is important to set proper names for the nodes.” manual This is the same discipline the TSC guide calls “the glue”, but the links point in a different direction:

Name rules the importer enforces
  • Node name = the Blender object name; the .msh file name = the Blender mesh datablock name. manual
  • Names may not contain |, % or #; lower-case words joined by _ are the convention. The LOD suffix is added automatically. manual
  • Everything after # is a comment and is dropped: use it to hide Blender's .001 or to give two LODs' nodes the same name. manual
  • |… after a name is a tag: material shortcode, |seat_<anim>, |bounding_box, |extent, |collider_list, |label, |draft_animal_…. manual
  • A name starting with / or modid::/ references an existing mesh or material instead of creating one. manual

4 · How the game puts a rail vehicle on the track

Consequence for the shared model: the bogie pivot you model is the pivot the game uses. There is no BogeyPivotX to disagree with the mesh. The TSC-side problem that the toolkit patches (bogie at 5.583 vs pivot 6.25) cannot occur in TF3. Conversely, a bogie origin that is “a bit off” in Blender is immediately visible in TF3 curves.

6 · The simulation: four numbers, not a curve set

landVehicle = {
  engines = { { power = 150, tractiveEffort = 30, type = "ELECTRIC" } },  -- kW, kN; HORSE/STEAM/DIESEL/ELECTRIC
  topSpeed = 19.444,            -- m/s  (70 km/h)
  weightEmpty = 14000,          -- kg
  weightMaxPayload = 5000,      -- kg added when fully loaded
  friction = 0.02,
  brakeDeceleration = 2.5,      -- m/s²
},

manual A vehicle may have zero (wagon), one or more engines. There is no throttle curve, no adhesion model you author, no brake pipe: acceleration follows from power, tractive effort, mass and friction; deceleration is a constant. The TSC simulation blueprint's numbers map onto this directly:

Balancing matters more than realism here: TF3 is a tycoon game, and the manual asks that strong vehicles carry higher noise/pollution (emissions.noise.score / pollution.score 0–100, or −1 for automatic). manual

7 · Passengers, cargo and seats

None of this exists in TSC; all of it is required in TF3 for the vehicle to be useful:

  • transportVehicle.compartmentsList: compartments → loadConfigs → cargoEntry with capacity, cargoTypeSet (classes/types included or excluded), optional loadIndicator and seats; toHide lists nodes hidden in that configuration. manual
  • seatProvider: drivingLicense (RAIL…), optional crewModels, and seats[], each with animation (driving, driving_upright, idle, sitting, walk), crew, forward, group (anchor node) and a 16-value transf. Seats can be placed in Blender as empties named …|seat_<anim> or …|seat_crew_<anim> and are imported. manual
  • loadSpeed (≈ number of door lanes, or −1), comfortFactor, arrivalDelay/departureDelay in ms, which should equal your door animation lengths. manual

8 · Locomotive, wagon, multiple unit

KindFolderDistinguishing metadata
Locomotive/vehicle/trainlandVehicle.engines non-empty; transportVehicle.engineTransportModes set (e.g. ELECTRIC_TRAIN); usually a crew seat. manual
Wagon / coach/vehicle/wagonNo engines; compartments define passengers or cargo; transportModes TRAIN (and ELECTRIC_TRAIN if it may run under wire). manual
Tram/vehicle/tramCarrier TRAM; same events plus blinkers. manual
Multiple unit.mu.lua next to the .mdl filesvehicles = { { name = "x.mdl", forward = true }, … }; the game sums the technical data. A vehicle with multipleUnitOnly = true is never sold alone. manual
Reversible train–First, last and every motorised vehicle have transportVehicle.reversible = true; parts switch with the …_forward/backward_parts_on/off events. manual

The TSC “engine vs wagon” split (TSC guide Part 1 §7) therefore maps cleanly: the same two Blender models become a TF3 locomotive and a TF3 wagon, and the TSC “tender” becomes either part of a multiple unit or a wagon with no capacity.
