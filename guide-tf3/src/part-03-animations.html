Animations for TF3: events, strips and direction-dependent parts

The same keyframes you made for TSC's .ia files become TF3 .ani files, but they are triggered by game events, not by control values. This part lists the rail-vehicle event vocabulary, how to name strips in Blender, and how pantographs, doors, wheels and lights map.

3 · Keyframe rules

Rules the Model Editor validates manual
  • The first keyframe must be at time 0 (“has keyframes starting after 0”).
  • An animation needs at least one keyframe; time stamps and transforms must match in number.
  • Position-mapped channels (ship rudder, aircraft control surfaces) use keyframes 0 → 1000 with 500 as the middle; rail vehicles have none of these, but the same “0…1000 maps to a state” idea applies if you write a transformator that scrubs an animation.
  • Durations are real time: a 48-frame door at 24 fps is 2 s; set arrivalDelay = 2000 to match. manual
  • Rest pose at frame 0, as in TSC. The LOD-0 FBX is exported at frame 0.
  • Keep the TSC habits: scale applied, origins on hinges, linear keys where the motion is mechanical.
  • Door/lamp “off” animations are usually one keyframe hiding or moving the part; the paired “on” animation shows it. Both must exist.

4 · Wheels and rods

Plain axles: no animation at all

Nodes listed in railVehicle.config.axles are rotated about their y axis by the game from the speed and the mesh radius. manual This covers every TSC boNNwhNN wheelset. Do not key them.

Rods, cranks, valve gear

Key one revolution of the driving wheel and the rods together and put the strips under drive (speed-mapped) or wheels (length mapped to one rotation). manual Driving wheels that move rods should then not also be in axles, or they would be rotated twice check.

5 · Doors and the arrival/departure delays

  1. Model each door leaf as its own object (origin on the hinge or slide axis), named e.g. door_l1, door_r1.
  2. Key open and close as two actions, or key open 0→N and close as the reverse; export both as strips open_doors_left and close_doors_left (right side likewise).
  3. Set transportVehicle.arrivalDelay and departureDelay in ms to the longest open / close animation. manual
  4. Set loadSpeed to roughly the number of door lanes, or −1 for automatic. manual

TSC doors (DoorsOpenClose control, toggled or Lua-driven) need no re-keying: the open action becomes the open event strip, played in reverse for close if you prefer a single action.

Crew seats follow the same idea: a seat with forward = true and group = "headlights_fwd" is shown only when that mesh is shown, so the driver appears at the leading end. manual

7 · Pantographs: the TSC-to-TF3 translation

In TSC a pantograph is a toggled .ia on FrontPantographControl, raised by the player. TF3 has no player and no pantograph event; the manual's suggestion is “switching pantographs depending on the location in train” with the parts on/off events. manual Two workable approaches:

A · Mesh swap (no transformator)

Export the pantograph twice: a raised instance (keyed at the raised pose) and a lowered instance. Give the raised one back_forward_parts_on/off (rear pantograph up when the loco is at the front… or whichever convention your prototype used) and the lowered one the opposite pair. Instant, robust, no code.

B · Animated raise (transformator)

Keep the TSC raise animation as a strip named e.g. panto_raise and write a transformator that triggers it when the consist starts moving or when the position changes (Part 5). More work; looks better in depots.

For the Texas Electric trolley poles the same two options apply: the pole frame range 0–100 from the TSC spec becomes a single .ani; the game-driven “dewire” gameplay has no TF3 counterpart, only the visual (Part 5 §6).
