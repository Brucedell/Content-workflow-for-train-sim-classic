Where the pipelines branch

Both games want the same thing from Blender: a clean, correctly scaled, well-named model with its moving parts keyed. After that they diverge completely. Train Sim Classic wants an .igs plus XML blueprints and a per-vehicle Lua script; Transport Fever 3 wants FBX files, one per level of detail, imported by its own Model Editor, which writes the .mdl/.msh/.mtl files and holds the vehicle's metadata. Nothing from the TSC blueprint side is reusable in TF3, and nothing from the TF3 metadata side is reusable in TSC. The model and its animations are.

What the supplied manual covers, and what it does not

Covered (49 pages)
  • Model Editor: UI, loading/saving, FBX import rules, naming of nodes/materials/textures, animations via NLA strips, lights, seats, emitters, bounding box, labels, bulk import, validation messages, icons, options.
  • Vehicle Basics: emissions, transportVehicle, compartments, seats, sound.
  • Vehicle Types: landVehicle, road/rail/water/air structs, animation events, multiple units.
  • Advanced: transformator scripts, reversible trains and direction-dependent parts, buy-menu groups, fake bogies.
  • Repaint mods; API index.
Not in the supplied pages check
  • Mod Definition (mod.json, modinfo.json fields), Resource Types & Structure, the .mdl / .msh / .mtl reference pages, Guidelines & Requirements (polygon and texture budgets), Best Practices, Publish a mod, External Tools.
  • The material shortcode table the import names rely on.
  • Where this guide needs those, it states what is known from the covered pages and from Transport Fever 2 practice, and marks it check. Fetch those wiki pages before your first real import.

How to use this set

Read Part 1 to understand what TF3 wants, then Part 2 before you touch the shared model: three habits (origins on hinges, separate axle objects, a driver empty) cost nothing in TSC and save a day in TF3. Use Part 7's Export Prep for every TF3 export so the shared scene never drifts.
