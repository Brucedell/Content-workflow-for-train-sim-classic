4 · Writing the copy: a formula

Paragraph 1 · The machine (what it is, in design terms)

“Take command of the 500-horsepower Class EF-4 ‘Mountain Titan’. Built to conquer unrelenting mountain gradients…” Lead with the class, nickname and the one number railfans quote. No corporate names.

Paragraph 2 · The challenge (what the player must manage)

“…operators must look past basic throttle handling and actively monitor circuit overvoltage, exponential self-ventilation cooling curves, and cumulative thermal brake fade. Run too fast, and face a permanent, Pro-Mode axle hotbox seizure.” Name three mechanics and one consequence.

Paragraph 3 · The framework (why buying one makes the next better)

“Full compatibility with the Advanced Simulation Framework: inspection report (Shift+I), maintenance loop (Shift+O), open texture directories.” Link to the Framework page.

Keep each paragraph under 60 words. The spec grid carries the detail; the copy carries the feeling.

6 · Demos, proving grounds and pre-orders

Demo tiers (“short and deep”)

  • Never call it a demo on the page: “Plano Proving Ground Edition”, “Mechanics Preview Pack”.
  • 5–10 miles or one vehicle, with the full framework intact. Price $0–12.
  • Its product page carries the same viewer and spec grid as a $40 product, so buyers see the standard.

Greenlight block (pre-orders)

  • Interactive model + spec sheet + a funding bar: “$2,100 of $7,000”.
  • Tiers from the analysis: ≈ $1,500 proving ground → ≈ $3,500 fleet expansion → ≈ $7,000 full route. Ask for 20–30% more than you need to cover fees.
  • Pre-orders live on the provider (most support them); the bar on your site is a number you update.
  • Backers get a “Founders” skin or early access; say so on the block.

7 · Dev log, docs and support

  • Dev log: one post per milestone with a viewer embed of the WIP model, three screenshots and the next milestone. Doubles as the crowdfunding progress feed.
  • Docs: one page per product: controls, hotkeys (Shift+I, Shift+O…), known issues, FAQ. Plus the Framework page describing the shared mechanics once.
  • Compatibility board: a table: product · version · framework version · game version tested. Updated with each release (Part 6).
  • Support: an email address and a public thread or Discord. State response times you can keep.
