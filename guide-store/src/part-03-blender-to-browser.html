From Blender to the browser: the web GLB

3 · The poly diet and baking

  1. Duplicate the LOD-1 model into a “web” collection (or let the add-on decimate static parts on the fly with a triangle budget). Keep the master untouched.
  2. Delete what the camera never sees: cab interior, underframe detail below the solebar, bolts, interior walls of closed boxes.
  3. Decimate static parts (Decimate modifier, Collapse 0.3–0.6) but not hotspot parts: doors, pantograph arms, wipers keep their silhouettes.
  4. Merge static parts per material (body + roof + underframe) so the node count drops; moving parts stay separate objects.
  5. Bake the high-poly detail onto the low-poly duplicate: normal map, ambient occlusion, and the colour with baked AO if the game textures had none. Cycles ▸ Bake, Selected to Active, cage on.
  6. Apply scale and rotation (as for both games); origins stay on hinges.
Reuse the TF3 textures

The TF3 branch already produced albedo, normal and metal/gloss/AO sheets. glTF wants almost the same set (base colour, normal, metallic-roughness with AO), so the web branch costs you no new texture work: roughness = 1 − gloss, which the packer script can produce (Part 7).

5 · Hotspots: tagging what is clickable

  • Choose 3–8 hotspots per vehicle: the things the product page talks about (doors, pantograph/trolley pole, cab door, headlight, a signature mechanism).
  • Make the clickable mesh big enough to hit on a phone; tag the frame or base when the moving part is thin (the pantograph arms are 12 cm wide, the base is 1.6 m).
  • The viewer walks up parents on a click, so tagging a parent covers all its children.

6 · Animations as named clips

glTF stores animations as named clips; the viewer plays a clip by name. Blender's exporter can name clips from NLA tracks, and the add-on pushes each tagged action into a track/strip named after web_anim (the same push the TF3 branch makes, so one scene serves both). Objects sharing a clip name (two pantograph arms, two wipers) merge into one glTF animation. demo

  • Key the open state only; the viewer plays the clip backwards on the second click (“close”).
  • Frame 0 = rest; 12–30 frames at 24 fps; linear or ease-out keys; no scale.
  • Looping things (wipers, fans) are still exported once; the viewer plays once per click. Make the clip a full cycle so it returns to rest.

7 · Export settings

By hand (File ▸ Export ▸ glTF 2.0)

  • Format: glTF Binary (.glb)
  • Include: Selected Objects (the web collection)
  • Transform: +Y Up ✓
  • Mesh: Apply Modifiers ✓, UVs ✓, Normals ✓
  • Material: Export, Images: Automatic
  • Animation ✓ · Group by NLA Track ✓ · Sampling ✓ (force) · Limit to playback range ✗
  • Compression: off for the first test (Draco needs a decoder in the page; add later if size matters)

With the add-on (Part 7)

  • TSC sidebar ▸ Web viewer ▸ Output folder = your site's models/
  • Model name, triangle budget (60,000), max texture size (2048)
  • Export web GLB + manifest
  • Reads: LOD-1 objects, skips TSC-only parts, decimates static parts if over budget, pushes tagged actions to NLA strips, exports with the settings on the left, writes the manifest.
  • Reports triangle count, file size, oversized textures.

8 · Checking the result before it goes online

  1. Copy the .glb and .manifest.json into store-demo/models/ and add the manifest path to MODEL_POOL in index.html.
  2. Start the local server (Part 5 §1) and open the page. The status line shows triangles and animation count.
  3. Click every hotspot button and every part; hover labels should match. Watch for: a door opening the wrong way (key direction), a part jumping at the start (rest pose not at frame 0), black materials (missing base colour), see-through faces (flipped normals: Mesh ▸ Normals ▸ Recalculate Outside).
  4. Resize the window to phone width; orbit with touch if you can.
  5. Check the file size in the browser's Network tab (F12) and the frame rate while orbiting.
