The website in Blender terms

A website is a folder of files on someone else's computer (a server) that a visitor's browser downloads and draws. That is the whole trick. Everything else is detail about which files, who hosts them and what happens when a button is pressed. The files map onto things you already know:

Conventions and a glossary

TermMeaning (and the Blender idea it resembles)
BrowserChrome, Firefox, Safari, Edge: the program that downloads and draws pages. Think “the viewport plus a file loader”.
Server / hostA computer that keeps your files online. “Static host” = only files, no logic; that is all the landing site needs.
DomainThe name people type (yourstudio.com). Rented yearly; pointed at your host and your store.
HTML / CSS / JSContent / look / behaviour. See Figure 0.1.
glTF / .glbThe web's 3D file format; .glb is the single-file binary version. Blender exports it natively.
three.jsA JavaScript library that renders 3D in the browser (WebGL). The viewer uses it. It is the “render engine”.
WebGL / WebGPUThe browser's graphics API. Every modern browser, phone included, has WebGL.
CDNContent delivery network: a public host for libraries and big files. “Linked library” in Blender terms.
RaycastFinding what is under the mouse. The viewer does what Blender does when you click an object in the viewport.
ManifestA small JSON text file the viewer reads: which model, which parts are clickable, which animation each plays. Written by the add-on.
Storefront providerGumroad, Payhip, Lemon Squeezy, itch.io, Shopify…: the rented half (Figure 0.2).
Checkout / gatewayThe payment page and the company moving the money (Stripe, PayPal). Inside the provider.
Digital deliveryThe provider's time-limited download link and the customer's account library.
Licence keyA code the provider generates per sale; optional, used if your installer checks it.
Pre-order / greenlightSelling before shipping; the funding model from the opportunity analysis (Part 6).
demoShown working in store-demo/ (headless browser test, screenshots in Part 4).
checkProvider fees, limits and menus change; confirm on their site.
How to use this set

Read Parts 1 and 2 to decide what the store is. Then do Part 3 with one real vehicle: when your own model spins in the demo viewer on your own machine (double-click store-demo/index.html through a local server as Part 5 shows), the rest is uploading and writing. Keep Part 6 as the operating manual once sales start.
