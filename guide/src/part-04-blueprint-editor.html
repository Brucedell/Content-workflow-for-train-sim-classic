1 · The blueprints you need and the order to build them

Start from a copy, not a blank

Copy the Kuju sample blueprints into your product folder and rename them. A blank blueprint has dozens of fields with no obvious defaults; a working sample already has valid brake, air and control structures. Then change what you understand and verify the rest. Keep the Developer\Addon provider/product in references only if you really use that folder; otherwise re-point every reference.

2 · How BPE2 stores values (and why unit labels lie)

A value typed in BPE2 is stored twice: the real <Value> the game reads, and a ToolData block recording what you typed (mTypedIn) and the unit label shown (mUnits). Some files have no ToolData at all (the sample engine and Bogie 01) and are equally valid. verified

<Attribute name="MaxForce"><sFloat32><Element>
  <ToolData> … mUnits = "Lb/f"  mTypedIn = "35.296001434326172" … </ToolData>
  <Value>35.296001</Value>          <- the number the game uses
</Element></sFloat32></Attribute>

Boolean fields use eTrue/eFalse; enums are strings (eVacuumSinglePipe, eDoubleCab). Lists are wrapped in __Indexed__… elements; an empty list is <Element><Value/></Element>.

4.4 Brakes

The LocoBrakeAssembly question

The project's handoff document states that an empty <LocoBrakeAssembly /> crashes newer TSC builds. Both Kuju samples ship with an empty indexed list (<Element><Value/></Element> inside the attribute), which is a different XML shape. Safe practice: never hand-write a self-closing LocoBrakeAssembly; if your build is unstable or you want an independent brake, populate a loco-only brake that mirrors the train brake and add an EngineBrakeControl. check the crash claim on your build.

5 · The engine blueprint

5.1 RenderComponent

  • GeometryID: the exterior IGS path (relative to the product, e.g. RailVehicles\Electric\EngineSample\Default\Engine\Sample_Engine t3.igs).
  • CollisionGeometryID: a simple hull IGS (the sample uses a separate file).
  • PrimaryNamedTextureSet/Secondary…: the digits texture set used by primarydigits.
  • AnimSet: one entry per exterior .ia: AnimationID (your name), AnimationName (path), AnimateInEditor.
  • ShadowType, CastsShadows, DetailLevelGenerationRange: leave as the sample unless you know why.

5.3 Children (ContainerComponent)

Child entities attach other blueprints at a position: head/tail light sources, particle emitters (the 7F's Main Smoke Stack → Particles\Example_Smoke.xml), sound emitters. The ChildName is how Lua reaches it (Call("Main Smoke Stack:SetEmitterRate", r)). The sample electric has no children. verified

The simulation recognises its inputs and outputs by these exact names check which ones your subsystem reads before renaming anything. Your own custom names (e.g. TrolleyPoleFront) are ignored by the simulation and are free for scripts and animations.

The cab (InteriorInterface)

InteriorGeometryID = cab IGS, NumberOfCabs = eSingleCab/eDoubleCab, InteriorCamera = cab camera blueprint, CabOcclusion optional. The head-out camera and DriverPosition matrix live on the rail vehicle component.

7 · Wagons and tenders

A wagon is built exactly like an engine minus the powertrain. check exact class and field names against a stock wagon in your BPE2 (New ▸ Wagon blueprint), since no wagon sample was supplied:

  • Same Blender rules: bo01/bo02, wheels, origin on the rail, LODs, shadows, numbers.
  • Rail vehicle data: mass (empty and loaded if the wagon carries cargo), friction, bogies, couplings, collision.
  • Brake equipment must match the loco (air twin pipe vs vacuum), or the train brake does not propagate.
  • No engine simulation, no cab. Controls only if a script or animation needs them (doors, tail lamps).
  • Scripts are allowed: doors, loads and lamps are typically driven by OnConsistMessage from the loco (Part 5).
  • Tenders are their own type; a steam engine with TenderRequired = eTrue needs one coupled to run.

8 · Exporting and previewing

  1. Save every blueprint (BPE2 validates as you save and highlights broken references).
  2. Right-click the vehicle blueprint (or its folder) ▸ Export. BPE2 compiles the blueprint and everything it references into Assets\Provider\Product\…: geometry, textures, animations, curves and Lua (.out). Read the output pane for errors.
  3. Use Preview to open the compiled vehicle in the asset preview, check textures, LODs and “Animate in editor” animations. If an animation looks stale, close the preview and clear its cache (BRIAGE §9.1.1).
  4. Test in game (Part 6).
Never export into a route that is open

Exporting to an enabled provider/product while the TSC route editor has it loaded, then reloading the product, can corrupt the route on save (BRIAGE §9.1.3). Close the game before exporting.
