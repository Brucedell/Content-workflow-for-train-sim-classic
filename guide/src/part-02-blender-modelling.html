Modelling in Blender for TSC, and exporting geometry with BRIAGE

Build the model so that the exported .igs already has the node names, origins, LODs and materials the blueprints expect. Most of the rules here exist because a blueprint will later refer to something by name or position.

BRIAGE rules are quoted from the BRIAGE user manual v2.5.786 (section numbers given as “BRIAGE §x”). Numbers in examples come from the Kuju sample electric's Blender scene and its raw geometry export.

1 · Set up the .blend once

  1. Units: Scene ▸ Units = Metric, Unit Scale 1.0. One Blender unit is one metre in game.
  2. Orientation: the vehicle's front points along +Y; X is to the right; Z is up. (Blender Y becomes TSC Z on export.)
  3. Origin: the world origin is the centre of the vehicle on the rail head. The body object's origin sits exactly at (0, 0, 0) and the bottom of every wheel touches Z = 0. (BRIAGE §3.3: “the pivot of the main body… must be centred with z = 0 at the rail contact”.)
  4. Location on disk: save the .blend inside RailWorks\Source\Provider\Product\RailVehicles\…\YourVehicle\, with textures in a sub-folder on the same drive (BRIAGE §9.3).
  5. One scene per model: BRIAGE stores its export settings per scene (BRIAGE §4), so keep the exterior, the cab and each wagon variant in separate scenes of the same .blend. They can share materials, bogies and textures.
  6. Frame 0 is the rest pose. BRIAGE sets the current frame to 0 while exporting the IGS (BRIAGE §8.4.1). Everything must look “parked” on frame 0: pantographs down, doors shut, levers at their minimum.
  7. Frame rate: choose one rate for the project (the sample scenes use 24 fps) and never change it; BRIAGE writes fps × Frame rate Multiplier into each .ia (BRIAGE §5.1–5.2).

2 · The object naming scheme

Every exported object is named LOD level, visible distance and base name. The prefix is consumed by the exporter and turned into LOD data; the base name is what ends up as the node name the blueprints refer to. Verified on the sample: Blender 1_0500_bo01 becomes node bo01 in the geometry. verified

Keywords and merging

With Hierarchy processing on (the default), BRIAGE merges objects that share the same LOD level and distance into one node, to keep draw calls low, unless they contain a TSC keyword or a custom keyword (BRIAGE §4.7). Built-in keywords ($ = digit): _locomotive _tender _coach _vehicle _wagon _carriage _coal _fuel_level_ _freight _bulk _lights_fwdhead _lights_revhead _lights_fwdtail _lights_revtail _door$$ _step$$ _wh$$ _bo$$ _panto$$ _wiper$$ _primarydigits_$.

The merging rule that breaks animations

If an object must move on its own (a lever, a door, a pantograph arm, a con-rod), it must stay a separate node. Either give it a keyword name (door01, panto01_part02) or add its full name to BRIAGE's Custom keywords table. Otherwise it gets merged into the body and its animation silently moves nothing. After exporting, check the “Groups list” in the log to see what was merged (BRIAGE §8.4.2, §10.3).

Limits: 256 objects per IGS including LODs (BRIAGE §8.4.1) and 24 children per node in the IGS format (BRIAGE §4.7). Merging is how large models stay under them.

4 · Origins, pivots and transforms

Apply scale. Always.

IA files carry position and rotation but no scale (BRIAGE §8.5.2). Unapplied or negative scale is “known to cause untraceable bugs” (BRIAGE §9.8). Select all ▸ Ctrl+A ▸ Scale before every export. Apply rotation on static objects too; on animated objects, apply before you start keyframing (BRIAGE §9.9).

Modifiers are evaluated but not applied to your scene on export (BRIAGE §3.3), and n-gons are allowed. Mirror and Array are safe to keep live.

5 · Bogies and wheels

  • bo01 is the front bogie, bo02 the rear (BRIAGE §3.3). The front is +Y in Blender.
  • Wheels are children of their bogie, named bo01wh01, bo01wh02… Number them front to back to keep blueprints readable (the sample does).
  • Wheel radius: measure the mesh, not the drawing. Centre height must equal radius (bottom of the tyre on Z = 0).
  • Single-truck vehicles (the 1890s streetcar) use one bogie with BogeyPivotX = 0. A two-axle wagon without bogies still needs a “bogie” entry per axle group in the blueprint; model it the same way.
  • Steam: the 7F has a front pony truck bogie at +5.151 m and a second bogie entry at 0 (the coupled wheels). Rods and valve gear must not be merged; use custom keywords (BRIAGE §10.3 walks through exactly this case). verified

6 · Materials and TSC shaders

A TSC material is a shader name + an ordered list of texture slots + a few parameters. Blender's own shading is ignored; only what BRIAGE's material panel records is exported. Pick the shader first, because it decides how many slots you need (“Failing to use the right number of texture slots… will generate an error on export”, BRIAGE §6.1.1).

Performance

“The number of polygons impacts the game's fps far less than a high number of materials” (BRIAGE §8.7.1). Atlas your textures and aim for a handful of materials per vehicle; the sample exterior uses 11, most of them the five number digits.

7 · Textures and texture paths

  • Use power-of-two sizes (512, 1024, 2048…). BPE2 converts them to .TgPcDx on export.
  • Filenames: one dot only (the extension). Extra dots make BPE2 misread the extension, so BRIAGE appends .safe (§9.7). The Kuju samples use a [00] prefix convention ([00]sample_engine_id01). verified
  • Texture path mapping (BRIAGE §4.5): “write from *.IGS destination” (new mode, recommended) points the IGS at the files Blender uses. Set a Textures directory so every texture is routed to one folder (e.g. …\Engine\Textures).
  • Same drive for .blend, textures and export target, or the texture is dropped with “Please export to the same drive…” (§9.3).
  • Animated textures (flashing beacons): name frames x_anim1.dds, x_anim2.dds…, tick Animate UVs with #Frames and FPS, then force-export the extra frames in BPE2, since only frame 1 is referenced by the IGS (BRIAGE §6.4).

8 · Special objects

Lights

Two halves: the glow mesh in Blender (light_fwdhead, light_fwdtail, light_revhead, light_revtail, additive material) and the actual light source, which is a child entity added in the vehicle blueprint's ContainerComponent. The keywords _lights_fwdhead etc. keep the meshes separate so the game can switch them with direction.

Running numbers

Object 1_yyyy_primarydigits_N (N = digit count), faces assigned to materials primarynumber_0 (units), primarynumber_1 (tens)… using TrainDecal.fx. The blueprint's named texture set supplies digit images and the numbering CSV supplies the numbers (BRIAGE §10.6). Each TextureName entry must be exactly one ASCII character.

Shadows

Low-poly closed shells, named 1_0400_shadow_<part>, parented to the part they shadow at local origin, material shadow_… with StencilShadow.fx. The sample has one per body, bogie and wheel. verified

Collision geometry

The sample references a separate collision IGS (Sample_Engine.IGS) in addition to the box in the blueprint. A simple closed hull is enough.

Snap points (scenery only)

“Arrows” empties named #ss_, #st_, #sb_ + name, Z pointing outwards, no children (BRIAGE §8.2).

9 · Levels of detail

  • LOD n+1 is a child of LOD n with the same base name and a larger distance (1_0500_engine → 2_1200_engine). Break any of the three and you get “Inconsistent LODing” or offset objects (BRIAGE §9.10).
  • Keep the LOD twin at local (0,0,0) under its parent.
  • Watch hidden twins. The sample hides 2_1200_engine in the viewport. With Visible children ticked BRIAGE exports only visible children (§4.2), so a hidden LOD disappears. Either untick Visible children or keep LODs visible in a dedicated collection.

10 · The cab

The cab is a separate IGS (sample_cab.igs), referenced by the engine blueprint's InteriorGeometryID. Build it in vehicle coordinates, in place at the front of the loco. The sample cab spans 7.22–9.16 m forward and its throttle sits at (−0.808, 2.183, 8.709) in file axes. verified

  • Give every control its own object with its origin on the hinge and its rest pose (the control's minimum) on frame 0.
  • Duplicates such as 2_0000_throttle/3_0000_throttle in the sample are LOD levels (the cab GEO has LOD controllers with 2 and 3 levels, all at max distance), not pressed/released states. verified
  • Glass uses weatherglass_N materials if you want rain and wiper effects.
  • With NumberOfCabs = eDoubleCab the sample uses one cab model for both ends. check how your build treats the rear cab before modelling a second one.

  1. Run the toolkit's Validate (Part 7). Fix every ERROR.
  2. Press Export in BRIAGE's IGS panel; target …\Default\Engine\YourLoco.igs (cab: …\Default\CabView\YourLoco_cab.igs).
  3. Open the system console (Window ▸ Toggle System Console) and read the short log: name substitutions, the Groups list, materials with shader/first texture/UV arguments, and the texture list (BRIAGE §8.4.2).
  4. Only then go to BPE2 (Part 4).
