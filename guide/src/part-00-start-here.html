The pipeline at a glance

Every Train Sim Classic (TSC) vehicle goes through the same five stages. Blender makes the shape, BRIAGE converts it into the game's intermediate formats, Blueprint Editor 2 (BPE2) describes what the shape is (mass, bogies, controls, physics, scripts), the export step compiles everything, and the game loads the compiled result.

Where the friction actually comes from

Converting a model is rarely hard because of one big problem. It is slow because of many small disagreements between three descriptions of the same vehicle: the Blender scene, the exported geometry, and the XML blueprints. The sample electric locomotive supplied with this project shows every one of them:

The guide's strategy is simple: make Blender the single source of truth for anything geometric, generate or patch the blueprint fields from it, and check the links automatically (node names, animation IDs, control names) instead of by eye. Everything behavioural (physics, controls, scripts) stays in BPE2 and Lua, where it belongs.

Before you start: tool versions

Check your Blender ⇄ BRIAGE pairing check

The BRIAGE manual supplied with this project (v2.5.786) is written for Blender 2.7x: its material panel uses the Blender Render/Game engines and texture slots, which were removed in Blender 2.8. The Blender scene reads of the sample loco, however, show layered actions (“1 layer, 1 slot”), a feature of Blender 4.4 and later.

So before you begin, confirm which BRIAGE build you have and which Blender it runs in. Two workable set-ups:

  • Single Blender: a BRIAGE build that supports your modern Blender. Material options may sit in different panels from the 2.7x manual, but the concepts in Part 2 (shader name, texture slot order, IGS options) are the same.
  • Two Blenders: model and animate in a modern Blender, then open or append the model into a Blender 2.79 install that runs BRIAGE 2.5 and export from there. The TSC Toolkit targets Blender 4.2+; run its checks in the modelling Blender.

Folder layout you will work in

Rules that save hours

  • Work inside Source\Provider\Product. Save the .blend and all textures on the same drive; BRIAGE refuses to reference textures across drives.
  • Pick your Provider and Product names once. Every blueprint reference stores them (the samples use Developer\Addon).
  • One vehicle = one folder. Share bogies, textures and scripts between variants by pointing blueprints at the same files instead of copying them.
  • Avoid dots in file names apart from the extension (BRIAGE appends .safe otherwise) and avoid spaces in anything a script will name.
  • Keep the .blend under version control (git works well; the repo holding this guide is one).

Glossary

TermMeaning
BlueprintAn XML file describing one kind of object (engine, wagon, bogie, simulation, scenery…). Edited in BPE2, compiled to .bin.
BPE2Blueprint Editor 2, the Kuju/DTG tool shipped with TSC for editing blueprints and exporting (compiling) them.
BRIAGEBlendeR Intermediate Animation and Geometry Exporter: writes .igs (IGSE module) and .ia (IAE module).
.igs / .GeoPcDxIntermediate geometry (from BRIAGE) / compiled geometry (from BPE2 export).
.iaIntermediate animation: node positions and rotations over time, no scale.
Node / transformA named object inside the geometry (e.g. bo01, throttle). Blueprints refer to nodes by name.
LODLevel of detail: alternative versions of a node shown at different camera distances.
Control valueA named float on a vehicle (e.g. Regulator). The shared “bus” between cab, physics, script, animation and sound (Part 1).
SubsystemThe powertrain model inside an engine simulation blueprint: diesel-electric, electric or steam.
ConsistA train: an ordered list of vehicles coupled together.
serz.exeTSC's converter between .bin and .xml. Useful for inspecting compiled files.
LogMateTSC's log viewer. Lua print() output and engine messages appear here.
How to use this set

Read Part 1 once. It explains why every later rule exists. Then keep Parts 2–6 open as a checklist while you build, and install the toolkit from Part 7 on day one: it is cheaper to catch a naming or pivot mistake in Blender than after an export round-trip.
