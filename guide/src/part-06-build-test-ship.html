1 · The iteration loop

You changed…Redo
Mesh shape, UVs, materials, texturesBRIAGE IGS export → BPE2 export of the vehicle
Object names or hierarchyIGS and every .ia (names must match) → re-check blueprint links (crosscheck) → BPE2 export
An animationThat .ia only → BPE2 export; clear the preview cache if it looks stale
Bogie/wheel/coupler positionIGS → toolkit Measure + Patch → BPE2 export
Blueprint values onlyBPE2 export
Lua onlyBPE2 export (compiles .out); reload the scenario
CSV curvesBPE2 export of the simulation blueprint
Close the game before exporting

Exporting into a provider/product the route editor has loaded can corrupt the route on save (BRIAGE §9.1.3). Many changes also only take effect after the vehicle is re-placed in the scenario (BRIAGE §10.6).

2 · Getting the vehicle into the game

  1. Export from BPE2 so the compiled files exist under Assets\Provider\Product.
  2. Start TSC, open a route in the editor, and in the object set filter enable your Provider and Product check (menu names vary by release).
  3. Drag the engine (or wagon) from the rolling-stock browser onto the track. Build a short train with a matching-brake wagon.
  4. Save as a test scenario (Free Roam or Standard) and drive it. Keep one test scenario per vehicle; re-place the vehicle after blueprint changes.
  5. Optional: a consist blueprint (loco + wagons) makes the train reusable in scenarios check Quick Drive listing rules on your build.

3 · The test drive, in order

Test in this order: each step depends on the previous one, so a failure early saves you chasing symptoms later.

#CheckIf it fails, look at
1Vehicle appears, textured, right way roundGeometry path, texture paths, front = +Y
2Sits on the rails, not floating/sunkOrigin on rail head, wheel radius = centre height
3Couples to the wagon without a gapCoupling pivot/receiving matrices, coupling blueprints
4Spawn state: brakes released, controls at sensible valuesDefaultValue of each control
5Brakes charge and releaseAir system / ejectors, compressor, pressures
6Moves on throttle; wheels spin at the right speedCurves vs MaxForce, Powered, axle NodeIds, radius
7Bogies turn on curves, not ahead of or behind the meshBogeyPivotX vs mesh
8Every cab control clicks and moves with its valuePickTransformName, .ia range, linear keys
9Exterior animations (pantograph, wipers, doors)AnimSet IDs, AnimStyle, node merging
10Gauges read correctly across their rangeControl min/max vs dial calibration
11Lights by direction and at night; numbers displayLight children, light meshes, digits set
12LODs switch cleanly at distanceLOD distances, hidden LOD twins
13Script features; LogMate shows no errorsPart 5
14Reverse direction, other cab end, AI drivingDouble cab, MaxPermissibleSpeed, GetIsPlayer gating

4 · Looking inside compiled files

TSC ships a converter, serz.exe, that turns compiled .bin blueprints into readable XML and back. The raw geometry dumps supplied with this project (cHcGeometry XML with TransformName, SourceLToPTransform, LOD controllers and materials) were produced by a conversion of this kind. Use it to:

  • confirm what BPE2 actually compiled (values, paths),
  • list the node names in an exported model and feed them to tsc_crosscheck.py (--geo, --cabgeo),
  • study how stock vehicles solve a problem you are facing.
serz.exe "Assets\MyProvider\MyProduct\...\MyLoco.bin"   → MyLoco.xml
python tools\tsc_crosscheck.py --engine MyLoco.xml --geo MyLoco.geo.xml --cabgeo MyLoco_cab.geo.xml

check serz's exact command-line options on your install; it lives in the RailWorks folder.

5 · Shipping

  • Ship the Assets files your vehicle needs (blueprints .bin, geometry, textures, animations, curves, .out scripts, sounds). Include Source only if you want others to modify it.
  • Package with the TSC package manager (.rwp) or a zip that mirrors RailWorks\Assets\Provider\Product. check
  • List dependencies (other products your blueprints reference, e.g. Kuju coupling or particle blueprints).
  • Do not redistribute Kuju/DTG sample files as your own; re-author anything copied from samples.
  • Ship with DEBUG alerts off and print spam removed.

6 · Troubleshooting: symptom → cause → fix

6.1 In Blender / BRIAGE

SymptomCause → fix
“No mesh or empty object found”Nothing selected/visible for the chosen export mode → select, or unhide (BRIAGE §9.2)
“Please export to the same drive…”Textures on another drive → move textures or use path tools (§9.3)
Wrong number of texture slotsShader expects N slots → see the shader table in Part 2
“Inconsistent LODing”, offset objectsLOD child not under LOD n−1, different base name, smaller distance, or 24-char truncation clash (§9.10)
Name changed in logMissing/bad L_DDDD_ prefix → rename (§10.4)
Settings seem ignoredUnapplied scale → Ctrl+A Scale, re-export with Verbose (§9.8)

6.2 In BPE2 / preview

SymptomCause → fix
No textures in previewTexture path mapping mode or directory → check the IGS log (§9.4)

Animation doesn't play“Animate in editor” off, merged node, name mismatch, stale cache (§9.5)
Export error on a Lua fileSyntax error → fix and re-export
File with extra dots misbehavesBPE2 treats text after the first dot as extension → rename (§9.7)
