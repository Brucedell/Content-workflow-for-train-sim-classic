Lua scripting: custom features on top of the simulation

Scripts cannot rewrite TSC's physics, but they can read and write every control value, move animations, switch nodes, talk to the rest of the consist and show messages. That is enough to build trolley poles, thermal damage, interlocks and safety systems.

1 · Where scripts live and how they are compiled

  • A blueprint's ScriptComponent holds a path to a .lua file. The sample electric has two: the engine blueprint points at Sample_EngineScript.lua and the engine simulation blueprint at Electric Engine Simulation.lua. verified Keep your logic in one of them (normally the engine blueprint's) and leave the other empty or absent to avoid two scripts fighting over controls.
  • BPE2's Export compiles .lua to .out in Assets. The game runs the .out. A syntax error fails the export, so read the output pane.
  • Wagons and tenders can have scripts too (doors, lamps, loads).
  • TSC embeds an older Lua. Write conservatively: avoid the # length and % modulo operators and newer library calls. check the exact version against your build; the example script already follows this rule.

2 · The callbacks the game calls

Function you defineWhen it runsUse it for
Initialise()Once at scenario load, before the route is readyVariables; Call("*:BeginUpdate")
Setup()Once when the script is initialised (e.g. when the player clicks the consist)Player-specific setup
Update(interval)Every frame after BeginUpdate; interval = seconds since the last frameAll continuous logic
OnControlValueChange(name, index, value)When the player moves a cab controlIntercepting and filtering input
OnConsistMessage(id, content, direction)A message from another vehicle arrivesMultiple units, wagon doors
OnCameraEnter(cabEnd, carriageCam) / OnCameraLeave()The camera enters/leaves a cab or passenger viewCab sounds, occlusion
OnCustomSignalMessage(message)A signal or track marker on the route sends a stringVoltage zones, bad-wire markers
Once you define OnControlValueChange, you own every control write

Both Kuju sample scripts contain only one function, and it does exactly this:

function OnControlValueChange(name, index, value)
  if Call("*:ControlExists", name, index) then
    Call("*:SetControlValue", name, index, value)
  end
end

If you define the callback and forget to write the value back, levers stop working. Note the sample's test: ControlExists returns 1 or 0, and in Lua 0 is true (only nil and false are false). The Kuju check therefore always passes. Write == 1. verified

3 · The API: Call and SysCall

Call("target:Method", …) talks to an entity. "*:" means “this vehicle and all its children”; "Main Smoke Stack:" targets the child entity of that name. SysCall("Manager:Method", …) talks to game-wide managers.

Calls seen in design snippets but absent from the reference: Call("PlaySound", …), SysCall("ScenarioManager:ShowAlertMessage", …) (without Ext), SetTime. check before use. Sounds are normally driven by control values that the sound blueprint listens to, which is how the example script does it.

4 · The architecture every good vehicle script shares

  • Scale everything by interval (dt). Frame rates vary; per-frame probabilities (like the spec's math.random(1,500)) make behaviour depend on fps.
  • Gate expensive or player-only logic with GetIsPlayer. AI trains run the same script.
  • Do one-time work that needs a spawned vehicle in the first Update, not in Initialise.

  Call("*:Reset", pole.anim)

Tested behaviour

The offline test drives the script at 60 updates per second against a mock API and checks 14 behaviours: starts stowed, unstow swaps meshes, hoists and seats at preset frame 65, positions the animation at 0.65 s, stays up after release, double-tap de-wire, fall timing, power interlock on and off, the once-per-session reminder (and that it does not repeat), rolling re-wire, leading-pole detachment above 7.5 mph, and Alt+P preset cycling. All pass.

Spec numbers worth revisiting
  • The gameplay spec's bad-wire alert fires at 50–70 mph and faster risk decay starts below 40 mph, while leading poles detach at 5–10 mph. For an interurban these may be intended; for street running they are very high. They are constants at the top of the script.
  • The spec's pole range changed from 0.0–1.0 (original) to frames 0–100 (revision). The script follows the revision.
  • GetCurvature returns 1/radius in metres; the spec's formula has no unit, so the script uses curvature per km × mph × 0.1. Tune in game.

7 · Sketch: voltage selector and thermal damage

The advanced traction and thermal framework is a larger version of the same architecture. Its skeleton:

function Update(dt)
  local lineV   = gZoneVoltage or DESIGN_VOLTAGE          -- from OnCustomSignalMessage zone markers; fallback = design
  local mode    = get("VoltageSelector")                   -- 0 = 600 V parallel, 1 = 1200 V series
  local motorV  = (mode == 0) and lineV or lineV / 2
  local prop    = 0.5 * (motorV / 600)                      -- 0.25 starved, 0.5 normal, 1.0 overvolt

  -- Phase A: reversible heat; V² rule; fans scale with axle speed
  local heat    = stress() * (motorV / 600) ^ 2
  gMotorTemp    = clamp(gMotorTemp + (heat - cooling(mph)) * dt, 0, 100)
  -- Phase B: irreversible health loss at 100 %, flashover and spin-down stress
  if gMotorTemp >= 100 then gHealth = gHealth - MELT_RATE * dt end
  -- Phase C: virtual throttle
  set("Regulator", get("VirtualThrottle") * prop * 2 * (gHealth / 100) + jitter(gHealth))
end

Brake fade follows the same shape (heat ∝ brake × speed, fade multiplier down to 0.2, cooling when released) and writes a scaled brake value through a virtual brake control. Flat spots use a hidden brake control pulsed for one frame per wheel revolution. Everything the framework needs is covered by GetSpeed, control reads/writes, ActivateNode, emitters and alerts.

8 · Talking to the rest of the train

  • Call("*:SendConsistMessage", id, content, direction) sends a string along the consist; the receiver's OnConsistMessage(id, content, direction) fires.
  • Forward messages you don't consume, so they reach the far end (the reference's convenience function does exactly this).
  • Use your own numeric id range (e.g. 424200+) to avoid clashing with other vehicles' scripts.
  • Direction encoding is inconsistent in the reference (0/1 when sending, 1/−1 when receiving). check by logging both ends.
  • Typical uses: multiple-unit throttle and pantograph, door commands to wagons, tail-lamp control on the last vehicle.

9 · Debugging

DEBUG = true
function DebugShowAlert(message, timeout)
  if DEBUG then
    SysCall("ScenarioManager:ShowAlertMessageExt", "Debug", message, timeout or 2, 0)
  end
end
  • print() output and script errors appear in LogMate. A runtime error usually stops the script for the rest of the session. Check LogMate first when a feature “just stops”.
  • Show state on screen with alerts while developing; remove them or gate with DEBUG before release.
  • Test logic offline: keep game calls at the edges (Figure 5.1) and run the script against a mock, as tools/lua_mock/run_trolley_test.py does.
